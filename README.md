# Devinorium

A secure, self-hostable **Material 3** web UI for managing your [Devin CLI](https://devin.ai) work from anywhere — safely port-forwardable to the public internet.

> AGPL-3.0-only · Built in Rust · Powered by the Devin CLI

---

## What it is

Devinorium is a self-hosted web application that lets you drive the **Devin CLI** from a browser. It is designed for people who want to manage AI coding sessions, files, and workspaces from any device, including over the public internet, without compromising on security.

It is structured so that the AI backend is pluggable: today it uses the `devin` CLI, but new providers can be added by **creating one new file and editing one line** in the provider registry.

### Layout

```
+----------------------------------------------------------+
| Sidebar          |  Main content                         |
|                  |                                        |
|  Threads         |  Conversation / file manager / ...    |
|  - thread A      |                                        |
|  - thread B      |                                        |
|                  |  +----------------------------------+  |
|  Workspaces      |  | Chat prompt                      |  |
|  - ~/proj        |  +----------------------------------+  |
+----------------------------------------------------------+
```

- **Sidebar (left):** list of conversation threads and workspace switcher.
- **Main content:** the active thread's conversation, or the file manager.
- **Chat prompt:** send messages to Devin; supports text, code, and image attachments.
- **File manager:** choose and browse the directory where work is being done.

## Security model

Devinorium is built to be **the safest thing you can port-forward**.

- **Single role.** There is exactly one role — `user` — and it is the only role permitted to use the website. There is no admin role, no superuser, no escalation path. Role checks are enforced on every request via middleware.
- **Password + optional TOTP.** Accounts authenticate with an Argon2id-hashed password. TOTP (RFC 6238) is optional but recommended.
- **Invite-only registration.** New users can only be created with a single-use invite token generated by an existing user via the CLI. No open registration.
- **Rate limiting** on login, TOTP, and all write endpoints to defeat brute force.
- **CSRF protection** on all state-changing requests.
- **Security headers** on every response (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, a strict CSP, and `Permissions-Policy`).
- **Secure, HttpOnly, SameSite=Strict cookies** for sessions.
- **Constant-time** credential comparisons.
- **Audit logging** of every security-relevant action.
- **HTTP-only server** by design. Terminate TLS with a reverse proxy (Caddy, nginx) or expose it safely with **Cloudflare Tunnel** — no port forwarding required. See [docs/deployment.md](docs/deployment.md).

## Provider extensibility

Adding a new AI provider requires exactly two changes:

1. Create one new file: `src/providers/<name>.rs` implementing the `Provider` trait.
2. Add one line to the registry in `src/providers/mod.rs`.

See [docs/providers.md](docs/providers.md).

## Quick start

```bash
# Prerequisites: Rust 1.75+, the devin CLI on PATH, authenticated (`devin auth login`)

git clone https://gitlab.com/HttpAnimations/devinorium.git
cd devinorium
cp .env.example .env          # edit settings, set a strong ADMIN_BOOTSTRAP_PASSWORD
cargo run --release
```

Then open `http://localhost:7878` and log in with the bootstrap credentials.

## Configuration

All configuration is via environment variables (see `.env.example`).
